# TeachForth IDE

Browser IDE for TeachForth tutoring. Not VS Code, not a VM per student. One small Node process and a SQLite file.

## Run

- Local: `node server/index.js` from this directory. Default port `8787`.
- Tests: `node server/selftest.js`
- Azure, only after `az login`: `deploy/azure-up.sh`

Do not run `deploy/install-on-vm.sh` on the shared prod machine. It is for the Azure VM.

## Rules

- No public signup. An admin creates every account.
- Roles are admin, chapter lead, teacher, and student. A session lead is a normal teacher promoted for one block, not a separate account type. A teacher can open a student's code only when paired in a live block, or when they are that block's session lead. A chapter lead can open a student only when that student has a teacher in their live block. Students never see session reports, including in zip exports. Students also never see course pathways, skill marks, or the teaching guide. Those stay on staff routes and return 403 to a student, including for their own id.
- A student's TeachForth account is their GitHub account after they connect. Only repositories named `TeachForth-…` are shown, and new ones are private. Each one has a `.teachforth` file with that student's code. Closing commits with the student's token and deletes the local files. Only the student can commit. Teacher sandbox code stays on this server and is never pushed. Creating a repository is one GitHub call per name: extra clicks return the existing project and never invent a suffixed repo. Do not remove that lock or the GitHub write pace. Do not create a public student repository. A student cannot open a public TeachForth repository until they make it private. New and converted repositories invite `so10-k` as a read collaborator. `delete_repo` is in the OAuth scope only so GitHub allows that visibility change. Do not add a delete-repository feature. Students start a project from Home. The GitHub page is for connecting and syncing. Connect and Link again must stay visible on Home, the GitHub page, and the account menu whenever the link is missing or broken. Do not leave a "link GitHub" error with no button.
- Opening a project writes an audit row. Do not add a way to watch a student without that log.
- Student HTML runs in a sandboxed iframe (`sandbox="allow-scripts allow-modals"` without `allow-same-origin`). Do not add `allow-same-origin`. `allow-modals` is only so `alert`, `confirm`, and `prompt` work. The preview URL is `/preview/:id/` on the IDE origin. It is a login page plus that iframe. The sign-in card must stay hidden once `/api/me` succeeds; do not let a `display` rule override `[hidden]`. The iframe loads `/preview-site/:token/`, which is an unguessable capability URL, not a cookie session. That response must send `Content-Security-Policy: sandbox allow-scripts allow-modals` and must not be a same-origin document. Hidden and `.teachforth` files are never served there. The whiteboard object layer must use `pointer-events: none` so pen strokes hit the canvas.
- The editor's right pane is a terminal. The bottom line accepts commands: `python`, `node`, `java`, `gcc`, `g++`, `ls`, `cat`, `teachforth serve`, `help`. Play runs the same command for the open file. Python, Java, C, C++, and Node run in the server sandbox (`server/sandbox.js`, `server/tf-exec.py`, `deploy/tf-sandbox`). Production must refuse to run student code as the app user: the root-owned helper drops to `tf-run` with `unshare --net`, `prlimit`, and `setpriv`. Do not start student servers, bind ports, or run Next.js on the VM. `teachforth serve` only opens the private preview link.
- A session lead can mint a home link for 1 to 168 hours. That link is an unguessable URL on this always-on VPS (`/teachforth-home/s/…`), not a second account. It serves a light IDE with Save & Commit and no live class, whiteboard, or presence. The student's GitHub token is stored only in that session directory, mode 600, and deleted when the link ends or expires. Do not log it, commit it, or keep home sessions after expiry. Hidden files and `.teachforth` are not sent there. If the class VM health check succeeds, the link redirects to the class IDE. Opening a class project pulls GitHub when its saved revision is behind, so a home commit shows up. A GitHub pull must not replace diverged local files, and reloading the editor must not close the project. Do not run student code on this VPS. The home host token lives in `/var/lib/teachforth-home/token` and `/var/lib/teachforth-ide/home-token`, never in git.
- Only a teacher who can open a project can publish it. Publish copies static files, never `.teachforth`, to the prod host at `teachforthprojects.samsprojects.xyz`. Students cannot publish. Do not store a published site only on the Azure VM, because that VM turns off.
- Language runs use the sandbox above, not the browser teaching runners. The helper and `tf-exec.py` installed on the VM must be root-owned outside `/opt/teachforth-ide`. Hidden files and `.teachforth` are copied out of the run directory. A teacher can lock, hide, or keep a file off GitHub. A session lead can inspect the GitHub link, force a commit that names them, and relink or rename the TeachForth repo. Students never see hidden files or reports.
- No new npm dependencies. The server uses Node 24 built-ins, including `node:sqlite`.
- Authorized IDE hostnames are an admin list in the Domains page. Node writes only `DATA_DIR/domains.txt`. It may run `sudo -n /usr/local/lib/teachforth/tf-domains` with no arguments. That root-owned helper re-validates the list and writes only `/etc/nginx/sites-available/teachforth-domains`, then `nginx -t` and reload. A failed test restores the previous domain file. Do not pass a domain, a shell command, or a raw nginx snippet from Node. Do not replace the default nginx site. A certificate failure must leave HTTP working. The overlay deploy does not install or update the helper.
- Discord linking is an account-menu code, not a password. Slash commands are registered once, on the guild. The Python desk owns the gateway, including help buttons. Node answers slash commands only through `POST /internal/command`. The inbox is the Modmail fork in `/opt/teachforth-helper`, with the staff portal at `https://teachforthhelp.samsprojects.xyz`. Teachers register with `/login` or `.login`. In a ticket, `.teachforthlookup` and the helpdesk account panel show IDE role, projects, reports, skills, and history. They must not include passwords or tokens. The helper may start or stop the class server only for a Discord account that linked as admin while the class server was on. It does not run on the class VM. Slash commands reply with embeds and open buttons. They may post a project link, a name, or a role. A home link is sent as a direct message, or shown only to the session lead, never in a channel. They must not post code, notes, passwords, tokens, or GitHub tokens, except that after a student pastes a profile support code the staff ticket channel may show that account's files. Hidden files and `.teachforth` stay hidden. The grant stays out of Discord. The bot token stays in `/var/lib/teachforth-discord/config.json`. The Discord server ID is set from Accounts and is not hardcoded. Overlay deploy does not install the bot. Power from Discord goes through the power panel's localhost API, which rejects any request that came through nginx.
- Website role is the source of truth for bot permissions. The desk assigns Discord roles named TeachForth Student, TeachForth Teacher, TeachForth Chapter Lead, TeachForth Admin, and TeachForth Session Lead, and maps them to Modmail levels shown as Student, Teacher, Chapter Lead, Admin, and Owner. `.perms` uses those names. Session lead uses Teacher commands, plus `/home`. Session lead is only while that person leads a live block, and it is removed when class is off. Students get `/class`, `/projects`, `/share`, and `/ask`. Teachers get live class, find, and desk replies. Chapter leads also get `/block`. Only the current session lead or an admin gets `/home`. Only an admin gets `/power`, `/desk`, and `/logins`. A student cannot register for the helpdesk. Diagnostic commands (`.diagnostic`, `.projects`, `.project`, `.reports`, `.chapters`, `.helpmenusend`) require a linked teacher, chapter lead, or admin. `.diagnostic` asks for browser and device details, not cookie values. The IDE chat at `/chat.js` is signed-in chat. Discord is optional and only mirrors a linked account. A closed chat does not block the next one. `.roles` refreshes that person's Discord role; `.roles all` is admin and refreshes everyone. `.qualification add|remove|list` routes a ticket to staff who hold that topic. Admins see every ticket. A chapter lead sees a topic only when nobody is qualified for it. End chat on the website closes the IDE thread and the Discord ticket when one exists.
- Live updates go through Actions → Deploy, or `deploy/ship.sh`. It overlays named files only. It must not rsync `--delete`, start or deallocate the VM, touch `/var/lib/teachforth-ide`, or run `deploy/install-on-vm.sh`. Apply is off unless someone turns it on. A failed health check restores that overlay from `/var/backups/teachforth-class` or `/var/backups/teachforth-home`. See `deploy/SHIP.md`.
- The portal uses the TeachForth purple (`#a030c8` family). The editor stays the dark VS Code shell. Do not recolor the IDE activity bar, status bar, or whiteboard to match the portal. A student profile uses tabs (Library, Pathway, Reports) so the curriculum and report diffs are not one long scroll. The editor is a dark VS Code-style view: opened tabs only, explorer for the rest, hidden `.teachforth`. Ctrl/Cmd+/ toggles a line comment for the open file's language (`#`, `//`, `/* */`, or `<!-- -->`). Do not reset the editor from a poll or save while the user is typing. A remote save merges with the open buffer (`public/merge.js`); overlapping edits keep the local text. Only one sidebar pane is visible. See `deploy/SHIP.md` before updating the live VM. CodeMirror close-brackets, close-tags, and completion stay vendored. No new npm dependencies.

## Shutdown

The Azure VM stays off until someone starts it from the power panel (`deploy/power-server.js`). That panel sets a deadline and deallocates the VM when the deadline passes. Do not turn the daily 8:00 start or 9:30 stop back on. Idle shutdown may still deallocate a forgotten VM, but it must exit while `/var/lib/teachforth-ide/manual-hold` is in the future. Do not point either script at this prod machine.
